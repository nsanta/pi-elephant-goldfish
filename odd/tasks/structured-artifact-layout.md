# Structured artifact layout

EGM artifacts get a feature-scoped directory tree instead of one flat folder.
Design decided 2026-11-16 (proposal + user choices below); implementation
pending.

## Specs

- **S1**: "I want to use a directory and provide inside of it a better direectory strcuture for the documentation generated by this extesion, propose a solution and make a plan" (verbatim original request).
- **S2**: Layout is feature-scoped: `<artifact-dir>/egm/<feature-slug>/` holds a feature's `concepts_brief.md`, `design_draft.md`, and all `*_report.md` files; `egm_bootstrap` writes `<artifact-dir>/egm/bootstrap/bootstrap_report.md`. (User choice: "Feature-scoped (recommended)".)
- **S3**: Structured layout is the **default**; flat remains available via `EGM_ARTIFACT_LAYOUT=flat` (env var or `EGM artifact layout: flat` line in `AGENTS.md`, mirroring the existing artifact-directory marker). (User choice: "Structured by default".)
- **S4**: Repo policy constraints: vendored skills are never hand-edited — layout guidance enters skill text only via a new scripted adaptation class in `scripts/adapt-pi.mjs`; `UPSTREAM.md` documents it; `scripts/check-content.mjs` allowlist updated; docs updated (README config table, `docs/pi.md`, `docs/architecture.md`); behavior changes verified test-first.
