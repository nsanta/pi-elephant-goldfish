Using EGM with Pi

This package ports the Elephant-Goldfish Model (EGM) to the Pi coding agent.

What is different on Pi

This repository is a Pi package: the EGM skills, reviewer personas, and document standards are vendored content, while the harness-specific behavior lives in a Pi extension (extensions/) (internals documented in architecture.md) that registers four tools and a set of /egm-* commands on session start. Instead of your harness's native subagent and question tools, Pi sessions drive EGM through these extension-registered tools: egm_goldfish (zero-context reviewer spawning), egm_bootstrap (recursive directory documentation), egm_ask (single-select interactive gates), and egm_state (durable pipeline state); the /egm-* commands start each vendored skill by name (see Commands). The vendored skill text is byte-identical to upstream except for minimal scripted adaptations (see UPSTREAM.md and scripts/adapt-pi.mjs); never hand-edit vendored files.

Install

From a published git repository:

pi install git:github.com/<owner>/pi-elephant-goldfish

For development, load the extension from a checkout of this repository:

pi -e .

egm_goldfish launches pi --print subprocesses with no conversation history, restricted to read-only tools, and instructs each child to read the requested persona file from this package first. The extension fans reviewers out in parallel, collects their reports, and normalizes and deduplicates the findings itself, so no reviewer ever needs to nest another subagent.

Artifact directory and layout

The artifact root resolves from the EGM_ARTIFACT_DIR environment variable, then an EGM artifact directory: <path> line in AGENTS.md/CLAUDE.md, then the working directory. Inside it, artifacts are arranged structurally by default — one folder per design:

<artifact-dir>/egm/
├── <feature-slug>/          # concepts_brief.md, design_draft.md, *_report.md
└── bootstrap/bootstrap_report.md

Agree on a short kebab-case <feature-slug> per design at the first gate and reuse it for that design's brief, draft, and reports; pass the same value as egm_goldfish's slug parameter. Setting EGM_ARTIFACT_LAYOUT=flat (env var, or an EGM artifact layout: flat line in AGENTS.md/CLAUDE.md) restores the legacy flat layout, with every artifact written directly in the artifact root.

Commands

The extension registers seven /egm-* commands, one per vendored skill. Each command reads the skill's SKILL.md, strips the YAML frontmatter, and sends the body as your message (with your command arguments appended), so the model receives the upstream instructions directly. This is equivalent to running the corresponding /skill:egm-<name> skill command, but works identically in TUI, RPC, JSON, and print modes.

/egm-brainstormskills/egm-brainstormInteractive ideation and refinement of a half-baked concept.

Arguments pass through verbatim. For example, /egm-review docs/designs/foo.md uninterrupted runs the review pipeline on that document with the uninterrupted preset.

Tools

ToolRole
egm_askSingle-select interactive gate for EGM workflows (one question, 2-8 options; each option is a plain string or a {title, description} object, so ask-user-style option objects validate and render instead of failing schema validation). Falls back to plain chat when no interactive UI is available.
egm_goldfishSpawns zero-context Goldfish reviewers as read-only pi --print subprocesses, fans them out in parallel, and writes the consolidated report per the artifact layout (pass slug to file it under <artifact-dir>/egm/<slug>/; a number is appended on filename collisions).
egm_bootstrapRecursively bootstraps EGM contract README.md files: discovery, safety gate, pruning, partitioning, parallel read-and-write worker subprocesses, JSON return validation, root roll-up, and a mandatory final verification pass. Its own report is filed under <artifact-dir>/egm/bootstrap/ (flat mode: the artifact root). See Bootstrap.
egm_statePersists or returns the EGM review pipeline state for the current session branch (stored as durable session entries, so a long review survives compaction and branching).

The review pipeline itself is model-driven from the vendored skill text; the tools only provide the harness-specific mechanisms the skills describe.

Bootstrap

egm_bootstrap ports the upstream egm-bootstrap root orchestrator. Call it with path (the subtree to document, required) and optionally targetFilename (default README.md). The extension performs, deterministically: level-by-level BFS discovery (hidden/ignored directories skipped, .gitignore/.egmignore basenames honored), bottom-up pruning of non-code and test-only directories, adaptive partitioning, and a final verification pass. Documentation itself is written by fresh pi --print workers restricted to read,grep,find,ls,write,edit tools; each worker must end with a JSON subtree_index payload (one retry on invalid output, then placeholder entries), and a final root-compiler child rolls everything up into the root blueprint.

Safety gate: when more than 15 directories survive pruning and approved is not true, the tool returns an approval request instead of running. Present it to the user with egm_ask, and only re-call egm_bootstrap with approved: true after explicit approval.

The result reports the number of contract files written/corrected, the verification violation count, and the report path (<artifact dir>/bootstrap_report.md); read the report file for per-worker status and every violation.

Support status

Experimental but exercised: vendored content tracks upstream at pinned revision a8380ab (see UPSTREAM.md), and the extension-side runtime (egm_goldfish, egm_bootstrap, egm_ask, egm_state, the /egm-* commands) has been verified end-to-end against a real pi dev install.

What is verified (see Testing for the record and how to re-run):

  • Unit and content checks port the upstream suite's intent and thresholds (frontmatter schema, the 24,000-byte skill body limit, persona/standard coverage, link integrity, manifest, adaptation invariants, adapt-pi.mjs sync fidelity over a pristine upstream tree).
  • A headless, uninterrupted Goldfish review end-to-end: /egm-review on a fixture ran all five stages through 9 zero-context reviewer children and produced a consolidated report whose verdict caught every planted flaw.
  • A bootstrap end-to-end: egm_bootstrap on a 6-directory fixture wrote all contract files through parallel workers with 0 verification violations, and the >15-directory safety gate fired without spawning workers.

What is verified manually only: interactive multi-turn flows (brainstorm intake, draft section-by-section, review gates answered in the TUI). Follow the per-skill checklists in skills/*/TEST.md for those.

Testing

Run npm test (fast, offline; integration tests are env-gated behind EGM_E2E) and npm run check:content. Exact commands, the env-gated tier, and the recorded phase-by-phase harness verification evidence live in TESTING.md.

Known limits

  • TUI gates in RPC are forwarded minimally. egm_ask renders a native SelectList dialog in the TUI; in RPC/print mode the gate degrades to a plain-chat question instead of a structured dialog.
  • No artifact side-panel. Reports, briefs, and drafts land in the artifact directory as files; there is no pi-side UI surface listing them.
  • Named personas are emulated. Upstream harnesses register personas as native subagent types; on Pi, a persona is a vendored markdown file that each zero-context pi --print child reads before judging.
  • npm publish pending. Distribution today is the git repository (dev install via pi -e ., later pi install git:...); a published npm package is deferred to the release phase.
