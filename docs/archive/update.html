# Artifact Generation Rules

## 1. Trigger, Output & Auto-Open
- Whenever I ask for a UI, diagram, dashboard, report, visual explainer, or interactive tool, generate a single, self-contained HTML file.
- Save all artifacts in `./artifacts/` using a descriptive kebab-case filename (e.g., `./artifacts/q3-revenue-dashboard.html`). Create `./artifacts/` if missing.
- Never overwrite `./artifacts/_template.html`. Use it as the structural and styling reference for every new artifact.
- Every artifact MUST work directly over the `file://` protocol:
  - Keep all custom CSS and JavaScript inline inside the single HTML file.
  - Never use local `fetch()`, relative script/CSS imports, or ESM imports that fail under `file://` CORS.
  - Always use pinned UMD CDN builds (never floating `@latest` URLs).
- Immediately after writing or updating an artifact, open it in the default browser via bash:
  - macOS: `open "<file>"`
  - Linux: `xdg-open "<file>"`
  - Windows (PowerShell/Git Bash): `start "" "<file>"`

## 2. Design System & Palettes
- Copy the CSS variables, `THEMES` registry, layout shell, and theme switcher from `./artifacts/_template.html`.
- **Default Palette:** `dusk` (`#003f5c`, `#58508d`, `#bc5090`, `#ff6361`, `#ffa600` in light mode, with contrast-lifted dark variants and warm neutral surfaces).
- **Selectable Palettes:** Support switching via the header selector or prompt override:
  - `dusk` (default): Bold editorial spectrum for dashboards and general tools.
  - `editorial`: Warm paper & Prussian/terracotta for executive reports and finance.
  - `nordic`: Muted petrol & eucalyptus for architecture diagrams and engineering metrics.
  - `okabe`: High-separation colorblind-safe palette for dense analytical charts.
  - `botanical`: Balanced teal, iris, and moss for modern SaaS tools and growth metrics.
- If I specify a palette name in my prompt (e.g., "use nordic palette"), set `DEFAULT_PALETTE` in the generated file accordingly.
- **Typography & UI:**
  - Use `Inter` for UI/body text and `JetBrains Mono` with `tabular-nums` for all KPI numbers, metrics, IDs, and code.
  - Use `lucide` icons (`lucide@0.460.0` UMD) instead of mixed emojis or raw inline SVGs.
  - Default to light mode unless I ask for dark mode; always preserve the persistent Light/Dark toggle and Palette switcher in the sticky top bar.

## 3. Charts & Data Visualizations
- **Default Library:** Chart.js 4 (`https://cdn.jsdelivr.net/npm/chart.js@4.4.7/dist/chart.umd.min.js`).
- **Advanced Library (Only When Needed):** Apache ECharts 5 (`https://cdn.jsdelivr.net/npm/echarts@5.5.1/dist/echarts.min.js`) strictly for Sankey flows, heatmaps, treemaps, gauges, or zoomable financial series.
- **Chart Rules:**
  - Always wrap `<canvas>` in a `relative` container with an explicit height (e.g., `class="relative h-72 w-full"`) and set `responsive: true, maintainAspectRatio: false`.
  - Never hardcode hex colors inside datasets—pull colors from `getActiveTheme().series` and register every chart instance in the `charts` array so colors, gridlines, and text re-theme cleanly when toggling Dark Mode or Palettes.
  - For 2–3 series charts, skip adjacent indices for stronger contrast (e.g., `[0, 3]` or `[0, 2, 4]`).

## 4. Diagrams (Mermaid)
- **Library:** Mermaid 11 (`https://cdn.jsdelivr.net/npm/mermaid@11.4.1/dist/mermaid.min.js`).
- **Diagram Rules:**
  - Always initialize with `startOnLoad: false` and `theme: 'base'`, populating `themeVariables` dynamically from `getActiveTheme()`.
  - Store raw Mermaid definitions in JS (`MERMAID_DIAGRAMS`) so diagrams cleanly re-render whenever Light/Dark mode or the active palette changes.
  - Place diagrams inside a `.diagram-stage` card with Zoom (`+` / `-` / `Reset`), **Copy Source**, and **Export SVG** controls.

## 5. Content & Code Hygiene
- Strip unused starter sections from `_template.html` when generating a real artifact (e.g., omit the Mermaid script and diagram card if the request is a pure KPI dashboard, or omit Chart.js if it is a pure architecture diagram).
- Use real context from the conversation whenever available. If creating a mockup with sample data, generate realistic domain data and badge it as `Sample Data` in the header.

    function downloadSvg(id, filename) {

      const url = URL.createObjectURL(blob);
      const a = Object.assign(document.createElement('a'), { href: url, download: filename });

      URL.revokeObjectURL(url);

    function updateChartsTheme() {
      const t = getActiveTheme();
      charts.forEach((chart) => {
        chart.data.datasets.forEach((ds, i) => {
          const idx = ds._colorIdx ?? (i % t.series.length);
          const color = t.series[idx % t.series.length];
          if (Array.isArray(ds.backgroundColor)) {
            ds.backgroundColor = ds.data.map((_, j) => t.series[j % t.series.length]);
          } else {
            ds.backgroundColor = color;
          }
          if (ds.borderColor) ds.borderColor = color;
        });

        if (chart.options.scales) {
          Object.values(chart.options.scales).forEach((scale) => {
            if (scale.ticks) scale.ticks.color = t.textMuted;
            if (scale.grid && scale.grid.display !== false) scale.grid.color = t.gridLine;
          });
        }
        if (chart.options.plugins?.legend?.labels) {
          chart.options.plugins.legend.labels.color = t.textMuted;
        }
        if (chart.options.plugins?.tooltip) {
          Object.assign(chart.options.plugins.tooltip, {
            backgroundColor: t.surface, titleColor: t.text, bodyColor: t.textMuted, borderColor: t.border
          });
        }
        chart.update('none');
      });
    }

      const vars = {
        '--bg': t.bg,
        '--surface': t.surface,
        '--surface-muted': t.surfaceMuted,
        '--border': t.border,
        '--text': t.text,
        '--text-muted': t.textMuted,
        '--accent': t.accent,
        '--grid-line': t.gridLine
      };
      Object.entries(vars).forEach(([k, v]) => root.style.setProperty(k, v));

      localStorage.setItem('artifact-palette', state.palette);
      localStorage.setItem('artifact-mode', state.mode);

      document.getElementById('palette-select').value = state.palette;
      document.getElementById('theme-label').textContent = state.mode === 'dark' ? 'Light' : 'Dark';

      const icon = document.getElementById('theme-icon');
      icon.setAttribute('data-lucide', state.mode === 'dark' ? 'sun' : 'moon');
      lucide.createIcons();

      renderSwatchStrip();
      updateChartsTheme();
      renderAllMermaid();
    }

    document.getElementById('palette-select').addEventListener('change', (e) => {
      state.palette = e.target.value;
      applyTheme();
    });

    document.getElementById('theme-toggle').addEventListener('click', () => {
      state.mode = state.mode === 'dark' ? 'light' : 'dark';
      applyTheme();
    });

    // Boot
    initCharts();

4. How It Feels in Practice

Once those two files are in place, your prompts stay short and natural:

* **Default dashboard:** *"Create a dashboard comparing monthly cloud spend across AWS, GCP, and Postgres from `costs.csv`."* -> Generates `./artifacts/cloud-spend-dashboard.html` in **Dusk Spectrum** and opens your browser.

* **Palette override:** *"Build an interactive Mermaid sequence diagram of our OAuth2 token refresh flow—use the nordic palette."* -> Sets `DEFAULT_PALETTE = 'nordic'`, omits Chart.js to keep the file lean, and includes zoom + SVG export.

* **Iterative updates:** *"Add a doughnut chart for regional breakdown and switch the default to dark mode."* -> Edits the same HTML file in place and refreshes/opens it automatically.

One small customization worth considering later: if you generate artifacts from inside a codebase, you can add a one-line helper script or alias (e.g., `./artifacts/index.html` auto-regenerated on every artifact save) if you want a local gallery of everything your agent has built.
